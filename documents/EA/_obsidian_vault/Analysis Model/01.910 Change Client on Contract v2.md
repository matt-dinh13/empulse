# 🎯 01.910 Change Client on Contract v2

> **Type**: UseCase
> **Package**: HomerSelect/BSL/Analysis Model/Contract Management/Client on contract change/User Interface model

## 📝 Notes

This use case describes steps to change the client (i.e. CUID) on a chosen contract (it means another client on the contract is required).
User can assign an existing client, therefore new client has to be created in the CIF first.
CUID of an existing client is provided by user. System only checks whether the provided CUID exists in the CIF system by calling Customer Data.GetCustomerDataRequest 
For both cases are performed following steps:

	
- the contract documentation is moved under CUID of the new client in the Cabinet


	
- CUID of the new client is updated on the processed contracts

Finally, notification about the change client on contract is generated for external systems (LCS, CaBus AM, CMS,...)

Rules and possible issues related to using of this function:

	
- If an error is showed at create the new path data for the Document in the Cabinet, it is needed to check valid records in the DMS_File object. If missing, the error is returned.


The use case can be called via REST API endpoint:
POST /v9.0/contracts/{contractNumber}/changeClient
{
       "cuid": 12345678
}
