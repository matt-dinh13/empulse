# 🎯 03.050 Create Full Early repayment request manually

> **Type**: UseCase
> **Package**: HomerSelect/BSL/Analysis Model/Contract Management/Loan Service Processing/Loan Option CEL/Full Early Repayment/Access Rights

## 📝 Notes

After the client is familiar with amounts and accept conditions for the Early repayment of loan (ER) - see 03.035 Show early repayment preview , it is possible to create request for ER. The ER request contains information about amount which needs to be paid and about date when this amount needs to be paid.
Notice: This function is used for creating a new ER request. If you interested in browsing already created ER requests - see 03.200 Show ER request history.
Each request is stored to the contract for which is asked and it is valid until the ER due date. If a valid ER request for specific due date already exists when a new one is being created, the original request can be replaced with the new one.
A valid ER request is canceled when Grace period or Gift payment services are applied on the contract (see 08.220 Check and process Grace period or 08.210 Check and process Gift payment for more information)

If a print of a document related to ER request is required, there is needed to define particular document type as well as printout template for the Full Early Repayment service - see Setting of Early repayment printout addendum.
If the document and its print template are defined, the ER document printout is generated and stored to the ER request for its possible print. All these documents (printouts) are stored in the File Store (Cabinet) for further use.
If it is found that current client's payments on the contract are sufficient for ER, the system {DEL CBL-7209 CLM-2456}tries to perform the contract ER immediately after creating the ER request - see 03.100 Check and process Early repayment request use case.{/DEL}{ADD CBL-7209 CLM-2456}registers the contract for ER processing by generating ProcessFerAutomaticallySE.{/ADD} In other cases, ER request is waiting for a client's payment to perform ER and (by the service setting) a notification is sent to the installed collection system.
After the request expired without ER has been done, the client can ask for next ER.

Frequency of usage:
   A few requests a day created by back-office operators
Actor:
  Authorized user
