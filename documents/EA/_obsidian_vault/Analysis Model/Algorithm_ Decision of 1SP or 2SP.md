# 📋 Algorithm: Decision of 1SP or 2SP

> **Type**: Requirement · **Stereotype**: «Functional»
> **Package**: HomerSelect/BSL/Analysis Model/Contract Origination/Manage Product Offer/UseCase Model

## 📝 Notes

This algorithm defines which sales process will be selected for non-identified clients.
See also table in linked document.

Inputs:

	
- process defined on the product offer from OFS (not real offer generated by the product calculator) - optional(PO)
	
- flag on related Salesroom (FS) - values: '1SP', '2SP', '1and2SP' (it is retrieved from Salesroom Rest Controller API GET ( https://homesis.{environment}/homesis/restful/salesrooms/search?filter={variables}).
	
- flag on related Product Profile (FP) - values: '1SP', '2SP', '1and2SP'
	
- selected/missing documents in product search


Algorithm:
1. If CUID is defined 
    1.1. If PO = 'APPLICATION_CREATION_1SP' then one one-stage process is selected and this algorithm ends.
    1.2. otherwise, two-stage process is selected and this algorithm ends.
2. Otherwise (i.e. if CUID is not defined), system makes decision based on the following global parameters: IncludeDocInProductCalculator, OfferProductsWithMissingDocuments and global parameter RequireAtLeastPrimaryDocuments - see the next steps.
3. If IncludeDocInProductCalculator = "No": Sub-algorithm1 (note that it is not necessary to check documents in this case because user cannot select any documents in GUI)
4. Otherwise (i.e. if IncludeDocInProductCalculator = "Yes"), system decides based on the OfferProductsWithMissingDocuments parameter:
4.1. OfferProductsWithMissingDocuments = "No": Sub-algorithm1 (note that it is not necessary to check documents in this case because product calculation returns only offers meeting all document conditions)
4.2. Otherwise (i.e. if OfferProductsWithMissingDocuments  = "Yes"), system decides based on the global parameter RequireAtLeastPrimaryDocuments parameter:
4.2.1 If global parameter RequireAtLeastPrimaryDocuments = "Yes": Sub-algorithm2
4.2.2 Otherwise (i.e. if global parameter RequireAtLeastPrimaryDocuments = "No"): Sub-algorithm1 (note that it is not necessary to check documents in this case because user does not have to select any documents in GUI)

Sub-algorithm1:
1. If FS = '1SP', then one-stage process is selected and this algorithm ends.
2. If FS = '2SP' then two-stage process is selected and this algorithm ends.
3. If FS = '1and2SP' then system checks setting of the related product profile (one of the following three settings of FP is possible):
    3.1. If FP = '1SP', then one-stage process is selected and this algorithm ends.
    3.2. If FP = '2SP' then two-stage process is selected and this algorithm ends.
    3.1. If FP = '1and2SP' then decision is made as follows (on one the following two possibilities):
            - if the selected documents meet conditions of all applicable default document container(s) (i.e. default document containers assigned to the respective product retrieved according to the rule Get document containers for product), then one-stage process is selected.
            - if selected documents do not meet conditions of all applicable default document container(s), then two-stage process is selected and this algorithm ends.

Sub-algorithm2:
1. If the selected documents do not meet conditions of the default primary identification document container(s) and identification document container(s) (i.e. default document containers of type 'PRIM_IDENT' or 'IDENT' assigned to the respective product retrieved according to the rule Get document containers for product), no process is selected and this algorithm ends. If there is no such primary identification document container or identification document container bound to the product, this step is evaluated as met and the algorithm proceeds to next step.
2. System checks setting of the related salesroom (one of the following three settings of FS is possible):
    2.1. If FS = '1SP', system additionally checks selected documents (on one the following two possibilities):
            - if selected documents meet conditions of all applicable default document container(s) (i.e. default document containers assigned to the respective product retrieved according to the rule Get document containers for product), then one-stage process is selected and this algorithm ends.
            - if selected documents do not meet conditions of all applicable default document container(s), then no process is selected and this algorithm ends.
    2.2. If FS = '2SP' then two-stage process is selected and this algorithm ends.
    2.3. If FS = '1and2SP' then system checks setting on the offer:
           2.3.1. If PO = 'APPLICATION_CREATION_1SP' then one-stage process is selected and this algorithm ends.
           2.3.2. If PO = 'APPLICATION_CREATION_2SP' then two-stage process is selected and this algorithm ends.
           2.3.3. If PO is not defined, the system checks setting of the related product profile (one of the following three settings of FP is possible):
                2.3.3.1. If FP = '1SP', system additionally checks selected documents (on one the following two possibilities):
                      - if selected documents meet conditions of all applicable default document container(s), then one-stage process is selected and this algorithm ends.
                      - if selected documents do not meet conditions of all applicable default document container(s), then no process is selected and this algorithm ends.
                2.3.3.2. If FP = '2SP' then two-stage process is selected and this algorithm ends.
                2.3.3.3. If FP = '1and2SP' then decision is made as follows (on one the following two possibilities):
                      - if the selected documents meet conditions of all applicable default document container(s), then one-stage process is selected.
                      -  if selected documents do not meet conditions of all applicable default document container(s), then two-stage process is selected and this algorithm ends.

Notes:

	
- If some document container is empty (i.e. MinCountOfDocuments related to the DocumentContainer = 0), condition for such document container is evaluated as met.
	
- If there is no document container assigned to the product, related document-container-based conditions are evaluated as met.
